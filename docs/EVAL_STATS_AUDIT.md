# 评测脚本统计核查（2026-11-06）

对象：`scripts/_eval_serve_inner.py`（`eval_serve.py` 的内层进程）。
起因：夜间 P2 评测中，四次评测的“我方发球时摔倒率”都与“发球入界率”相同（82/79/77/80%）。

## 结论

1. **脚本确实有统计错误，但这些错误解释不了“摔倒率 = 入界率”。** 旧脚本只会**漏计**摔倒，不会多计。
2. **更可能是真实行为：** 成功发球后，机器人在球飞行的约 1.5–2 秒里倒地；发球失败的回合约 0.7 秒就结束，来不及倒地。默认奖励几乎不惩罚摔倒（`anti_fall` 只有 −0.1），500 轮短训学出扑倒式发球是合理的。
3. **这一点尚未实测确认。** 修正后的脚本会输出摔倒发生在击球前还是击球后、距离击球多久，重跑一次评测即可确认。
4. 此前我说“多半是统计假象，读到的是重置后的机器人”，判断有误：重置后读到的是准备姿势的高度（约 0.70 m），只会让摔倒**少算**。

## 依据（play 源码与 Isaac Lab 2.3.2）

- `play/dual_agent_env.py` 的 `step()`：物理子步结束后保存 `extras`，**在 `step()` 返回前**对已结束的球场调用 `_reset_idx()`，再执行 `write_data_to_sim()` 和 `sim.forward()`。
- `play` 的 `_reset_idx()` 会把 `just_hit[env_ids]` 清零。
- Isaac Lab 的 `write_root_link_pose_to_sim()` 会直接写入 `data.root_link_pose_w`。因此 `step()` 返回后，已结束的球场读到的是**下一回合的初始状态**。

旧脚本在 `step()` 返回后读取 `robot.data.root_pos_w` 和 `u.just_hit`，所以：

| 问题 | 影响 | 严重程度 |
|---|---|---|
| 回合结束那一步读到的是重置后的机器人（约 0.70 m） | 只在最后一个控制步才倒地的情况会被漏计；**只少算，不多算** | 小 |
| 回合结束那一步的 `just_hit` 已被清零 | 若击球和回合结束发生在同一控制步，这次击球会被漏计。发球时击球后至少要飞行数百毫秒才会结算，基本不受影响 | 小 |
| 二次击球判负仍计入“合法发球” | `legal` 偏高 | 中，违例率高时明显 |
| 超高发球计入“未击中” | 超高时 play 不登记这次击球，旧脚本把它同时算作 `height` 和 `no_hit` | 中，会夸大未击中 |
| 高度未减去球场原点 z | play 的球场原点 z 为 0，目前无影响 | 无 |

`served_in`（入界）的统计依赖 `rally_winner` 和整回合累计的 `ours_hit`，不受上述问题影响，**夜间的入界率数据仍然有效**。

## 已做的修正（本提交）

- 包装 `play` 的 `_reset_idx`，在重置**之前**记录我方机器人高度和本步击球；对已结束的球场使用这份快照。只做记录，不改 play 的规则代码。
- 二次击球不再计为合法；超高发球不再计为未击中。
- 摔倒高度改为相对球场原点，阈值可用 `--fall_height` 设置（默认 0.45 m）。
- 新增统计：
  - `fell_before_hit`：击球前摔倒的回合数；
  - `fell_after_hit`：击球后摔倒的回合数；
  - `timing_s`：从回合开始到击球、到摔倒、到回合结束的时间分布，以及击球到摔倒的时间分布（分位数 p10/p50/p90）。

修正只做了语法检查，**未在 Isaac 中运行**。

## 请远程 agent 做的验证（约 5 分钟）

用夜间那个 500 轮短训的导出模型重跑一次：

```bash
python scripts/eval_serve.py --play_root <play 路径> --ours <导出目录> --opponent zero --side 0 --num_envs 16 --rallies 50
```

判读：

- `serve.fell_after_hit` ≈ `serve.served_in`，且 `timing_s.fall_after_hit.p50` 在 0.3–1.5 秒：确认是**发球后真实倒地**。
- `fell_after_hit` 接近 0：说明还有别的统计问题，把完整 JSON 发回，并录 2–3 个回合的视频。
- 同时核对 `legal`、`no_hit`、`height`：修正后 `no_hit + height + legal` 应接近 1。

## 对 P3 的影响

- 如果确认是真实倒地，P3 已有对策：`fall` 每回合 −5，接球方和发球方都计；击球后发球方不再受 `hold_ready` 约束，但仍受 `fall` 约束。
- 在评测中，**发球后倒地不直接丢分**（每回合都会重置），但会让我方接不到对方的回球，也不利于 E 档“保持平衡”的展示。P3 的 M1 门槛中“摔倒 ≤10%”保持不变。
- 惩罚摔倒可能降低出球速度，从而降低入界率。P3 的 B 阶段要同时看 `in` 和 `fall`。如果两者此消彼长，先保证入界，再逐步提高摔倒惩罚。
- 训练侧（`serve_env.py`）不受同类问题影响：奖励和统计在 `_reset_idx` **之前**计算。
